# 发票识别与金额统计 — 技术方案

> 状态:**设计稿,暂未实施**。本文档为新增「发票识别与金额统计」菜单的模型选型与技术方案,供评审与后续开发参考。
>
> 日期:2026-07-16

---

## 一、背景与目标

在现有合同篡改检测系统(FastAPI + Vue3,已具备完善的多模态 LLM/OCR 基础设施)基础上,新增一个「发票识别与金额统计」菜单,支持:

- 批量上传发票(图片 JPG/PNG + PDF,一个 PDF 可含多张发票)
- 自动识别每张发票的关键字段
- 汇总【价税合计总额】及明细,支持报销核对场景

### 1.1 选型决策(已与需求方确认)

| 决策点 | 选择 | 理由 |
|---|---|---|
| 输入形式 | **图片 + PDF 都支持** | 覆盖拍照/扫描件/电子发票,报销场景最常见 |
| 统计口径 | **明细 + 价税合计总额** | 每张发票抽出字段并汇总总额,覆盖 90% 核对场景,输出清晰 |
| 识别引擎 | **端到端 VL 多模态模型直接抽取** | 复用现有 `LLMOCREngine`,一步到位,对版式宽容,无需训练 |

---

## 二、模型选型与技术路线

### 2.1 识别引擎:端到端 VL 多模态模型(复用现有 `llm_*` 配置)

把每张发票图片/PDF 页直接丢给**多模态视觉语言模型**,用一个结构化 prompt 要求其返回发票字段的 JSON,**一步到位**完成"看图 + 识字 + 结构化",不做 OCR → 文本 → LLM 两步拆分。

**为什么这样选:**
- 项目已接 SiliconFlow 平台的 VL 模型(当前 `data/llm_config.json` 配置可用),复用 `LLMOCREngine` 的请求 / 重试 / 日志 / 脱敏基础设施,**零新增依赖**。
- 发票是结构化、版式相对固定的文档,VL 模型对这类输入识别准确率高,对拍照倾斜 / 扫描件比纯 OCR 容错更好。
- 一步抽取避免 OCR 数字错误(金额、税额这类关键数字)在两步间传导。

**模型选型建议(默认值,可在设置页改):**

| 档位 | 模型 | 适用 |
|---|---|---|
| 推荐(默认) | `Qwen-VL-Max`(通义) / SiliconFlow 上的 VL 模型 | 中文发票(增值税专票 / 普票、电子发票)识别最稳,中文 + 数字混合强 |
| 兼容 | 任意 OpenAI 兼容协议的 VL 模型(GPT-4o 等) | base_url 指过去即可 |

**直接复用 `llm_*` 配置组(不新增 `invoice_*`)**:发票识别与合同 OCR 都是"多模态看图"任务,共用同一套 VL 模型配置更合理,避免设置页膨胀。仅新增发票专属的 prompt 和输出解析。

### 2.2 金额统计:明细 + 价税合计总额

输出 schema(每张发票一条明细 + 一条汇总):

```json
{
  "items": [
    {
      "source": "发票1.pdf | 发票1.jpg | 汇总PDF第1页",
      "invoice_type": "增值税专用发票 | 增值税普通发票 | 电子普通发票 | 其他",
      "invoice_no": "24412000000012345678",
      "invoice_date": "2026-07-01",
      "seller": "某某科技有限公司",
      "buyer": "某某有限公司",
      "amount": 10000.00,
      "tax": 1300.00,
      "total": 11300.00,
      "raw_total_text": "壹万壹仟叁佰元整",
      "confidence": 0.95,
      "parse_warning": null
    }
  ],
  "summary": {
    "count": 5,
    "total_amount": 50000.00,
    "total_tax": 6500.00,
    "total": 56500.00,
    "currency": "CNY",
    "warnings": ["第3张发票:金额+税额≠价税合计"]
  }
}
```

字段说明:
- `amount` 金额(不含税)、`tax` 税额、`total` 价税合计
- `raw_total_text` 原文大写金额,便于人工核对
- `confidence` 模型自评置信度
- `parse_warning` 异常备注(如金额 + 税 ≠ 合计)

后端做一道**强校验**:`|amount + tax - total| > 0.01` 时在 `parse_warning` / `warnings` 标记,不静默吞错。

## 三、后端实现(新增 `invoice` 子包 + 端点 + 任务)

遵循项目"领域分层 + 子包 + `__init__.py` 门面"范式,新增 `src/document_comparison/invoice/`。

### 3.1 新增文件

| 文件 | 职责 |
|---|---|
| `invoice/__init__.py` | 门面,export `run_invoice_pipeline`、`InvoiceItem`、`InvoiceReport` |
| `invoice/extractor.py` | **核心**:VL 模型调用(复用 `LLMOCREngine._chat` 的请求模式,自定义发票 prompt),把图片 → `InvoiceItem` |
| `invoice/pipeline.py` | 编排:输入归一化(PDF 渲染分页 / 图片直读)→ 逐页 / 逐张抽取 → 汇总 → 校验 |
| `invoice/models.py` | Pydantic 模型:`InvoiceItem`、`InvoiceReport`、`InvoiceSummary`(也可并入主 `models.py`) |

### 3.2 复用的现有基础设施(不改)

- `ocr/llm.py` 的 `_chat()` 请求模式 + `_to_data_url()` + `_extract_json()` → 抽成可复用调用,或直接在 `extractor.py` 照抄一份(后者更解耦,发票 prompt 与版面 OCR prompt 差异大)
- `parsing/pdf.py:render_pages()` → PDF 发票渲染为 PNG
- `parsing/pdf.py` 的 PyMuPDF → 判断 PDF 每页是否为单张发票
- 图片读取:新增 `extractor.py` 内一个 `_read_image_as_png(path)`(JPG/PNG 都转成统一 PNG bytes)
- `config.py` 的 `llm_*` 配置 + `apply_llm_overrides` → **不改**,直接复用
- `observability.py` 的 `log_model_request/response` → 复用
- `storage.py` → 新增 `save_invoice_report` / `load_invoice_report`(仿 `save_raw_report`,文件名 `{task_id}.invoice.json`)
- `tasks.py` → 新增 `run_invoice` 方法(仿 `run_raw`,挂到现有 `TaskManager`,复用 `_sem` 并发控制、`push_event` 进度、`_fire_callback` webhook)

### 3.3 新增 API 端点(在 `api/app.py` `create_app()` 内,仿 `raw-compare` 组)

```
POST /api/v1/invoice              多文件上传(files: List[UploadFile]),返回 task_id
GET  /api/v1/invoice/{task_id}    查询结果(含 invoice_report)
GET  /api/v1/invoice/{task_id}/events   SSE 进度(复用 task_manager.event_stream)
GET  /api/v1/invoice/{task_id}/report   下载 JSON 结果
```

多文件上传用 `files: list[UploadFile] = File(...)`,接受 `.pdf` / `.jpg` / `.jpeg` / `.png`。每张发票一个进度阶段,`push_event("invoice", frac)` 逐张推进。

## 五、关键设计决策

1. **不新增 `invoice_*` 配置组**:发票识别就是"多模态看图",与合同 OCR 同质,共用 `llm_*`。设置页无需改动,用户配好 VL 模型即可同时服务两个功能。
2. **发票 prompt 独立**:版面 OCR 的 prompt(返回 blocks / bbox)与发票 prompt(返回字段 JSON)差异大,在 `extractor.py` 写专属 system prompt,要求严格 JSON、字段缺省时返回 null 而非臆造。
3. **多文件 vs 单 PDF 多发票**:用户可一次拖入多个文件,也可拖入一个含多张发票的 PDF。后端统一把每个输入的"每个识别单元"(图片 = 1 单元,PDF = 每页 1 单元)送模型,汇总成 `items`。
4. **金额校验防线**:模型返回的 amount / tax / total 做加和校验,异常不抛错而是标记 warning,保证整批可出结果。
5. **异步任务复用**:`TaskManager` 现有结构(`run` / `run_raw`)直接加 `run_invoice`,并发上限、webhook、SSE、elapsed 统计全部白送。
